# NetMon 回線品質モニタ

マンションのインターネット回線で起きている **パケットロス・遅延・速度低下** を常時記録し、
**経路のどこで起きているか** を数値で示すためのツールです。
Windows 標準の PowerShell だけで動きます (インストール不要)。

## クイックスタート

1. [Releases](../../releases) から最新の zip をダウンロードし、好きな場所に展開する
   (Releases がない場合は「Code → Download ZIP」)
2. `start_netmon.bat` をダブルクリックして監視を始める (有線LAN推奨)
3. 1週間ほど計測したら `make_report.bat` を実行し、できた `report.html` と zip を確認・提出する

動作環境: Windows 10 / 11 (Windows PowerShell 5.1)。管理者権限は不要です。

## 使い方

| やりたいこと | 操作 |
|---|---|
| 監視を始める | `start_netmon.bat` をダブルクリック |
| PC起動時に自動で開始 (最小化) | `install_autostart.bat` を一度だけ実行 |
| 自動起動をやめる | `uninstall_autostart.bat` |
| 提出用レポートを作る | `make_report.bat` (直近7日分) |

監視画面のキー操作: `S` 速度測定を今すぐ実行 / `R` 経路を再探索 / `Q` 終了

> **有線LANでの計測を強く推奨します。** Wi-Fi だと「Wi-Fi の電波が悪いだけでは?」と言われてしまいます。

## 何を測っているか

1秒ごとに、次の地点へ同時に ping を送っています。

```
このPC → H1 宅内ルーター → H2 マンション設備 → H3〜 ISP網 → E1〜 外部サーバ
                                                            (Cloudflare / Google / Azure東日本 / AWS東京)
```

- **H1〜 (中継機器)**: tracert / mtr と同じ「TTL を制限した ping」で、外へ向かう実際の経路上の機器を自動で検出して計測
- **E1〜 (外部サーバ)**: Azure 東日本・AWS 東京をゲームサーバ相当として計測
- **自PCの通信量**: 同時に記録。「自分がダウンロードしていたせいでは?」という反論を防ぎます
- **速度測定**: 30分ごとに Cloudflare で下り(25MB)/上り(10MB)。測定中の数秒はロス集計から除外

### 「どこで詰まっているか」の判定

1分ごとに各地点のロス率を比べ、**ある機器から先の全地点 (外部サーバまで) でロスしている** とき、その手前との区間を原因と判定します。

| 画面/レポートの表示 | 意味 |
|---|---|
| 宅内 (このPC〜H1) | 自宅の LAN ケーブル・ルーター・PC 側の問題 |
| 宅内ルーター 〜 マンション設備 | マンション共用設備 (またはそこまでの配線) の問題の可能性大 |
| マンション設備 〜 ISP網 | マンションから回線事業者への回線 (共用回線の混雑など) の可能性大 |
| 中継機器より先 | 回線事業者のさらに上位網 |
| ○○ のみ | その宛先サーバ側の問題 |
| 中継機器の応答間引き | 機器が ping 応答を後回しにしているだけで実害なし |

※ 2発以上のロスがあったときだけ「異常」と判定します (単発のロスは記録はしますが判定しません)。

## 記録されるファイル (`logs\`)

| ファイル | 内容 |
|---|---|
| `raw\raw_*.csv` | **1秒ごと**の全地点の応答時間 (ms)。`LOSS` = 応答なし。過去分は自動で zip 圧縮 |
| `minute\summary_*.csv` | 1分ごと・地点ごとの送信数/損失数/応答時間 (最小・平均・95%・最大)/揺らぎ |
| `minute\overview_*.csv` | 1分ごとの概要 (外部・宅内ロス、判定、自PC通信量) |
| `incidents.csv` | ロス事象 (連続したロス) の開始・終了・損失数・完全断秒数・判定 |
| `speedtest.csv` | 速度測定結果 (測定直前の自PC通信量、測定中の応答時間も) |
| `events.csv` / `routes.csv` | イベント履歴、検出した経路の履歴 |

すべて Excel でそのまま開けます (BOM 付き UTF-8)。データ量は1日あたり生データ数MB (圧縮後 1MB 未満) 程度です。

## レポート

`make_report.bat` で `reports\report_期間_時刻\` に以下を作ります。期間を変えるときは:

```
powershell -ExecutionPolicy Bypass -File Make-Report.ps1 -Days 14
powershell -ExecutionPolicy Bypass -File Make-Report.ps1 -From 2026-10-01 -To 2026-10-09
```

- `report.html` … 結論 (自動文章)・区間別の結果・**日付×時間帯のロス率マップ**・ワースト時間・ロス事象一覧・速度測定結果・計測方法。ブラウザの印刷から PDF にできます
- CSV 一式 + 期間の生データ、および全部をまとめた **`.zip` (そのまま提出用)**

### 提出のコツ

- 最低でも **1週間** は計測すると、「夜だけ悪い」「毎日起きている」ことが示せて説得力が上がります
- レポートの「宅内ルーターまでのロス率 0%」と「自PCの通信が少ない時間帯でもロスしている」の2点は、こちら側に原因がないことの根拠になります
- 管理会社には「どの区間で」「いつ」「どれくらい」を、回線事業者には zip ごと渡すのが確実です

## 設定 (`NetMon.ps1` 冒頭の `$Config`)

- `Endpoints` … 宛先の追加・変更。ping に応答しないサーバは `Kind = 'tcp'; Port = 443` で TCP 接続時間を計測できます
- `HopLabels` … 中継機器の表示名。自室にルーターを置いていない場合など、`@{ 'H1' = 'マンション共用ルーター' }` のように変更
- `SpeedTestEveryMin` … 速度測定の間隔 (0 で無効)。データ量は 1回 約35MB (30分ごとで1日約1.7GB)
- `LossThresholdPct` … 異常とみなすロス率 (既定 2%)

## 負荷

実測で CPU 使用率は 1コアの約3% (16スレッドCPUなら全体の0.2%程度)、メモリは約150MB で、長時間動かしても増え続けません。
スリープ・LAN 抜けの間は「計測なし」として扱い、ロスには数えません。

## 安全性について

- **PC の設定は変えません。** bat ファイルの `-ExecutionPolicy Bypass` は、このスクリプトをその場で 1回実行するためだけの指定で、PC の実行ポリシー設定は変更しません
- **管理者権限は使いません。** 自動起動はユーザーのスタートアップフォルダにショートカットを置くだけで、`uninstall_autostart.bat` で消えます
- **外部への通信は次だけです。** 計測先への ping (Cloudflare `1.1.1.1` / Google `8.8.8.8` / Azure / AWS と経路上の機器) と、速度測定のための `speed.cloudflare.com` へのダウンロード/アップロード (中身はダミーデータ)。計測結果をどこかへ送信することはありません
- **記録はすべてローカルの `logs\` / `reports\` に保存されます。** これらには宅内の IP アドレスや経路情報が含まれるため、公開の場には貼らず、提出先 (管理会社・回線事業者) にだけ渡してください
- スクリプトはすべてテキストなので、実行前に中身を確認できます
